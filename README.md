# 🌸 Бутон — Telegram-бот цветочного магазина

Telegram-бот для цветочного магазина «Бутон»: подбор букета по параметрам, оформление и
сопровождение заказов, программа лояльности, напоминания о важных датах и панель
администратора для управления каталогом, заказами и статистикой.

Проект разработан как дипломная работа и рассчитан на запуск на слабом сервере
(Pentium, 3 ГБ ОЗУ, Linux) — без PostgreSQL, Redis, очередей сообщений и ML-моделей.

## Технологический стек

- **Python 3.11+**
- **aiogram 3.x** — Telegram Bot API, FSM, роутеры, мидлвари
- **SQLite + aiosqlite** — хранение данных (WAL-режим)
- **APScheduler** — фоновые задачи (напоминания, бэкапы, контроль заявок)
- **OpenPyXL** — выгрузка отчётов по заказам в Excel
- **Pillow** — обработка фотографий букетов
- **python-dotenv** — конфигурация через `.env`

## Установка и запуск

### 1. Клонирование и виртуальное окружение

```bash
git clone <адрес-репозитория> buton
cd buton

python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate
```

### 2. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 3. Настройка конфигурации

Скопируйте `.env.example` в `.env` и заполните значения:

```bash
cp .env.example .env
```

| Переменная               | Назначение                                                        |
|---------------------------|--------------------------------------------------------------------|
| `BOT_TOKEN`               | токен бота, выданный @BotFather                                    |
| `ADMIN_IDS`               | telegram_id администраторов через запятую (например `111,222`)    |
| `TIMEZONE`                | часовой пояс, по умолчанию `Asia/Yekaterinburg` (UTC+5)            |
| `DB_PATH`                 | путь к файлу SQLite, по умолчанию `data/buton.db`                  |
| `PHOTOS_DIR`              | папка для фотографий букетов, по умолчанию `data/photos`           |
| `BACKUP_DIR`              | папка для резервных копий БД, по умолчанию `backup`                |
| `MAX_PHOTO_SIZE_MB`       | максимальный размер загружаемого фото (по умолчанию 5)             |
| `SHOP_PHONE`              | телефон магазина, отображается клиентам                            |
| `MANAGER_REMINDER_HOURS`  | через сколько часов напоминать админам о необработанной заявке     |
| `BACKUP_KEEP_COUNT`       | сколько последних резервных копий хранить (по умолчанию 30)        |
| `BACKUP_TIME`             | время ежедневного бэкапа, формат `ЧЧ:ММ` (по умолчанию `03:00`)    |
| `REMINDER_CHECK_TIME`     | время ежедневной проверки напоминаний о датах (по умолчанию `09:00`)|

### 4. Инициализация базы данных

База данных и схема создаются автоматически при первом запуске (`init_db()`
вызывается в `main.py`). Дополнительных команд миграции не требуется.

### 5. (Опционально) Заполнение каталога демо-данными

Чтобы сразу протестировать подбор букетов, можно загрузить 15 демонстрационных
позиций каталога:

```bash
python -m scripts.seed_bouquets
```

Скрипт идемпотентен — если в каталоге уже есть букеты, заполнение будет пропущено.

### 6. Запуск бота

```bash
python main.py
```

При старте бот:
- инициализирует базу данных (если ещё не создана);
- удаляет вебхук и переходит в режим polling;
- запускает планировщик фоновых задач (бэкапы, напоминания, контроль заявок).

Для остановки используйте `Ctrl+C`.

## Команды клиента

| Команда       | Описание                                                              |
|----------------|------------------------------------------------------------------------|
| `/start`       | регистрация, согласие на обработку персональных данных, главное меню  |
| `/select`      | пошаговый подбор букета (повод, получатель, бюджет, сезон, настроение, цвет, любимые цветы) с топ-3 рекомендациями |
| `/profile`     | данные профиля и уровень программы лояльности                         |
| `/history`     | история заказов клиента                                                |
| `/favorites`   | список избранных букетов                                               |
| `/remind`      | управление напоминаниями о важных датах (за 7/3/1 день)                |
| `/loyalty`     | информация о баллах и уровне лояльности                                |
| `/help`        | справка по возможностям бота                                           |

В процессе подбора и оформления заказа бот собирает: повод, получателя, бюджет,
сезон, настроение, цвет, любимые цветы, ФИО и телефон получателя, адрес и время
доставки, комментарий (опционально). Если точного совпадения нет, бот предлагает
похожие варианты с пометкой об отсутствии полного соответствия.

## Панель администратора

Доступна только пользователям, чей `telegram_id` указан в `ADMIN_IDS`.

| Команда / раздел         | Описание                                                              |
|----------------------------|--------------------------------------------------------------------|
| `/admin`                   | главное меню панели администратора                                  |
| `/orders`                   | список активных заказов с пагинацией и кнопками смены статуса      |
| `/stats`                    | статистика за период (сегодня/неделя/месяц/всё время) и выгрузка заказов в Excel |
| `/add_bouquet`              | добавление нового букета в каталог (название, описание, цена, теги, фото) |
| `/edit_bouquet`             | редактирование любого поля существующего букета                     |
| `/toggle_bouquet`           | скрыть/показать букет в каталоге без удаления                       |
| `/delete_bouquet`           | удаление букета из каталога с подтверждением                        |
| `/set_price`                | быстрое изменение цены букета                                        |

Жизненный цикл заказа: `new → accepted → assembling → ready → delivery → completed`
(или `rejected`/`cancelled`). При оформлении нового заказа администраторам
приходит уведомление с кнопками «Принять»/«Отклонить»; при дальнейших статусах —
кнопки перехода на следующий этап.

## Рекомендации букетов

Подбор в `/select` использует взвешенный скоринг по параметрам:

- повод — 25%
- бюджет — 20%
- получатель — 15%
- цвет — 10%
- настроение — 10%
- история заказов клиента — 10%
- сезон — 5%
- популярность — 3%
- рейтинг — 2%

По итогам показываются топ-3 букета с фото, названием, ценой и описанием, а также
кнопками «Заказать», «В избранное» и «Показать ещё».

## Фоновые задачи (планировщик)

- **Резервное копирование** — ежедневная копия файла БД в `BACKUP_DIR`, хранится
  не более `BACKUP_KEEP_COUNT` последних копий (старые удаляются автоматически).
- **Напоминания о датах** — ежедневная проверка сохранённых дат и отправка
  напоминаний клиентам за 7/3/1 день.
- **Контроль необработанных заявок** — каждые 30 минут проверяется, нет ли
  заказов в статусе `new`, которые висят дольше `MANAGER_REMINDER_HOURS` —
  по ним администраторам отправляется напоминание.

Все задачи работают в часовом поясе, указанном в `TIMEZONE` (по умолчанию
`Asia/Yekaterinburg`, UTC+5).

## Требования к окружению

Бот рассчитан на запуск на слабом сервере (1 ядро, 3 ГБ ОЗУ): используется только
SQLite (без отдельного процесса СУБД), polling вместо вебхуков, без тяжёлых
зависимостей (ML/LLM, очереди сообщений, Elasticsearch и т.д.).
